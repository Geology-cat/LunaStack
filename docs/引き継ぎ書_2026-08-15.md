## 1. 今回実施したGUI変更（実施済み・検証済み）

### 1.1 プレビューの2倍/4倍ズームで画像がウィンドウ全体にはみ出す問題の修正

**症状**: 2倍/4倍にすると、プレビュー画像が自ビューの境界を無視して
左ペイン・右Inspector・下部バーの上に覆い被さって描画されていた。

**原因**: [PreviewView.mm](../LunaStackApp/src/PreviewView.mm) の `drawRect:` が
bounds外への描画を明示的にクリップしていなかった。AppKitはレイヤー裏付けや
スナップショット経路（`cacheDisplayInRect:`）では bounds外描画を素通しにする。

**修正内容**（すべて PreviewView.mm）:

1. `drawRect:` 冒頭で `[NSBezierPath clipRect:bounds]` により明示的にクリップ
2. パン量のクランプ `clampedPan:` を追加。「画像の端がビューの端より内側に
   入らない」範囲に制限し、画像をドラッグで画面外に捨てられないようにした
   - `mouseDragged:` はクランプ済みの値を保存（生値を貯めると戻し操作に
     「効かない区間」ができるため）
   - `setZoom:` で倍率変更時に収め直し
   - `imageDrawRect` は使う瞬間に必ずクランプ（ウィンドウリサイズ対応）

### 1.2 右Inspectorの工程タブ導入（ワークフローの分離）

**動機**: 解析→アライメント→スタック→結果確認・ウェーブレット・書き出しが
1列のUIに混在して分かりにくい、というユーザーフィードバック。

**修正内容**（[MainWindowController.mm](../LunaStackApp/src/MainWindowController.mm)）:

- Inspector最上部に `NSSegmentedControl` の工程タブを追加:
  - **1. 解析・スタック** = Alignment / Quality / Stack / Drizzle
  - **2. 仕上げ・書き出し** = Wavelet / Export
- スタック完了時（`finishJob:`）に自動でタブ2へ切り替え
- 別ファイル選択時（`selectQueueIndex:`）はタブ1に戻す
- 表示制御は `updateInspectorVisibility` に一元化
  （タブの選択 × セクション開閉の両方を見て組み立て直す。
  隠す条件を分散させるとタブ切替と開閉が互いの状態を壊すため）
- セクション見出しは `_sectionHeaders`（key→ボタン）で保持

### 1.3 テストフック追加

- `LUNASTACK_ZOOM`（0=全体/1=等倍/2=2倍/3=4倍）環境変数と
  `setZoomIndexForTesting:` を追加。ズームのはみ出しをスナップショットで
  機械的に検証できる

### 1.4 検証結果

| 項目 | 結果 |
|---|---|
| 4倍ズームのはみ出し | 修正前スナップショットで再現 → 修正後は消滅 |
| 最小サイズ 1000×640 + 2倍ズーム | レイアウト崩れなし・はみ出しなし |
| AP当たり判定の自己検証（座標変換を変更したため） | 132点中 不一致0 / 往復誤差 最大0.0000px |
| AP編集・プリセットの自己検証 | 問題なし |
| ctest（stackcore_tests + availability_guard_fires） | 全合格 |
| スタック完了→タブ2自動遷移 | スナップショットで確認 |

## 4. GUIの残改善候補（今回は未実施・小粒）

1. **進捗バーが完了後も塗られたまま見えることがある**。`finishJob:` は
   `setDoubleValue:0.0` を呼んでいるが、モダンmacOSのNSProgressIndicatorは
   値の変化をアニメーションするため、完了直後の一瞬は満杯に見える。
   実害は小さいが、`完了` 時は一度 `setHidden:` するなどの対処が考えられる
2. 中央ツールバーのフレームスライダーが狭い（最小幅80pt）。プレビュー下の
   余白に対して操作精度が低い
3. 警告バナー（プレビュー上部）は幅不足時に末尾切り捨てになる。UI設計書
   §7.2 は「操作ボタン付きバナー」を想定しているが、現状はテキストのみ
4. キュー右クリックメニュー（Finderで表示 / このファイルだけ処理）が未実装
   （UI設計書 §3.1）
5. ステータスバーのボタン幅が固定値（70/80/90pt）。ローカライズ時に溢れる
6. UI設計書 §5.3 のタイル描画・ミップマップは未実装（現状は全画面
   `CGImageRef` 1枚。448×448では問題ないが、月面の大画像＋Drizzle 3倍では
   再検討の余地あり）

## 5. 作業上の注意（このリポジトリの前提）

- **パスにコロンを入れない**（README冒頭参照。ビルドが壊れる）
- **macOS 10.13対応が絶対条件**: SwiftUI・Swift Concurrency・UNUserNotification・
  Metal前提は不可。availability違反はCTestの `availability_guard_fires` が検出する
  （このテストは「ビルドが失敗すること」を期待している）
- GUIは**MRC（手動 retain/release）**・xibなしの手書きAppKit。ARCではない
- `NSString` の書式に `%s` を使わない（UTF-8ではなくCエンコーディングで解釈され、
  日本語パスが化ける。過去に実害あり。MainWindowController.mm の注記参照）
- PreviewViewに `setFrame:` という名前のメソッドを作らない
  （NSViewの同名メソッドと衝突して即クラッシュ。PreviewView.h の注記参照）
- エンジン（libstackcore）はUI非依存を維持。GUIとCLIは同じ `run_job` /
  パイプライン関数を通す
- 決定論性を壊さない: 同一入力・同一設定なら出力はバイト単位で再現すること
- 検証には `sample-data/jupiter.ser`（2.6GB・4617フレーム）と
  `LUNASTACK_*` 環境変数によるスナップショット自己検証を使う
