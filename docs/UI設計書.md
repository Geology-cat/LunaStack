## 1. 設計原則

この5つを、個別の画面判断で迷ったときの拠り所とする。

### 1.1 AutoStakkert! / RegiStax の操作モデルを裏切らない

想定ユーザーはほぼ全員が既存ソフトの経験者である。概念はAlignment Point、
Drizzle、Wavelet layersと同じものを使うが、日本語UIでは略語だけを置かず、
「位置合わせ領域」のように意味が分かる名前と画面内の説明を優先する。
**「今までの手順がそのまま通じる」ことが、macOSネイティブであることの次に大きな価値**になる。

### 1.2 3つの主工程をUIにも出す

エンジンは品質評価、アライメント、スタックを別々に実行できる。
各工程は完了時に必ず停止し、利用者がグラフや参照画像を確認してから次へ進む。
アライメント結果はサイドカーに保存されるため、
**選択率だけ変えて再スタックするときは解析をやり直さない**。この速さはユーザーにとって
明確な利益なので、UI上でも「解析済み」バッジで可視化する。

### 1.3 長時間処理が前提

最低ティア（2010年頃のMac）では基準ジョブに40分かかりうる。したがって:

- 残り時間の推定を必ず表示する
- 処理中もプレビューのズーム・パンなどUIは応答する
- バッチは途中中断・再開ができる
- 完了時に通知を出す（ユーザーは席を外している）

### 1.4 パラメータの意味が分かることを、設定項目の多さより優先する

惑星スタックは「効くとは限らない処理」が多い。特にDrizzleは、オーバーサンプリング済みの
データに掛けても情報が増えない。**UIが黙って期待を持たせない**よう、条件付きの機能には
その場に注意書きを置く（§4.4）。

### 1.5 後処理は非破壊

ウェーブレット等の後処理はスタック結果を書き換えず、パラメータのみを保持する。
いつでも係数をゼロに戻せる。これがRegiStax的な「気軽にスライダーを動かす」操作感を支える。

## 2. ウィンドウ構成

単一ウィンドウの3ペイン構成（`NSSplitViewController`）。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ ⬤⬤⬤  LunaStack — jupiter_2026-08-09.ser                    [ツールバー]  │
├───────────────┬──────────────────────────────┬───────────────────────────┤
│ 左サイドバー   │ 中央: プレビュー               │ 右: Inspector             │
│ (220pt)       │ (可変)                        │ (280pt)                   │
│               │                              │                           │
│ ■ 入力キュー   │  ┌────────────────────────┐  │  ▸ Alignment              │
│   jupiter.ser │  │                        │  │  ▸ Quality                │
│   saturn.ser  │  │    [プレビュー画像]      │  │  ▸ Stack                  │
│   mars.ser    │  │    APオーバーレイ        │  │  ▸ Drizzle                │
│               │  │                        │  │  ▸ Wavelet                │
│ ■ 品質グラフ   │  └────────────────────────┘  │  ▸ Export                 │
│   ▁▃▅█▆▃▁▂▅█  │  [表示切替] [ズーム] [AP編集] │                           │
│               │                              │                           │
├───────────────┴──────────────────────────────┴───────────────────────────┤
│ 解析中 ████████████░░░░░░  62%   1,860 / 3,000 フレーム   残り約 1分20秒  ⊗ │
└──────────────────────────────────────────────────────────────────────────┘
```

- 最小ウィンドウサイズ: 1000 × 640 pt（10.13世代のノートでも収まる）
- 左右のサイドバーは折りたたみ可能（狭い画面でプレビューを広く使える）
- 下部のステータスバーは処理中のみ表示

## 3. 左サイドバー

### 3.1 入力キュー

`NSTableView`（1行 = 1ファイル）。

| 列 | 内容 |
|---|---|
| 状態アイコン | 未処理 / 品質評価済み / アライメント済み / スタック済み / エラー |
| ファイル名 | `jupiter_2026-08-09.ser` |
| 副題 | `3,000フレーム · 640×480 · 16bit · RGGB` |

- ドラッグ&ドロップで追加。フォルダを落としたら中のSER/AVIを再帰的に追加
- 右クリックメニュー: Finderで表示 / キューから削除 / このファイルだけ処理
- **「解析済み」バッジ**はサイドカー（`.lstk`）の存在を示す。選択率を変えた再スタックが速い

### 3.2 品質グラフ

`NSView` に Core Graphics で直接描画する。

- 横軸: フレーム番号（時系列） ⇄ 品質順ソート を切替可能
- 縦軸: 品質スコア（正規化）
- **選択率のカットラインを重ねて描く**。「上位10%」がどこで切れるかが一目で分かる
- カットラインはドラッグで動かせ、Inspectorの選択率と双方向に連動する
- 時系列表示は、雲の通過やピント変更が視覚的に分かるので診断価値が高い

## 4. 右Inspector

`NSStackView` にセクションを縦に積む。各セクションは開閉可能で、開閉状態を記憶する。

### 4.0 工程タブ（v1.1で追加）

Inspector最上部に4つの工程タブを置き、セクションを工程ごとに分ける。
全セクションを1列に積むと「解析の設定」と「結果への操作」が混ざって
今どの段階にいるのか分からない、という実使用のフィードバックへの対応。

| タブ | セクション |
|---|---|
| 品質評価 | 各フレームの品評価、入力のバイトオーダー・ビット深度 |
| アライメント | 位置合わせ方法、参照フレーム、位置合わせ領域 |
| スタック | フレーム選択、加算方式、Drizzle |
| 仕上げ・出力 | Wavelet / Export |

- 各工程の完了時は次タブへ切り替えるが、次工程は自動実行しない
- 別のファイルを選択したら「品質評価」に戻す
  （結果の無いファイルに仕上げのつまみだけが見える宙ぶらりんを避ける）

### 4.1 Alignment

| 項目 | UI | 既定値 |
|---|---|---|
| 位置合わせ方法 | ポップアップ（複数領域 / 画像全体のみ） | 複数領域 |
| 対象モード | セグメント（惑星 / 月・太陽） | 自動推定 |
| 位置合わせ領域の大きさ | ポップアップ（32/48/64/96/128/200 px） | 画像サイズから自動提案 |
| 位置ずれの探索範囲 | スライダー + 数値（±8〜±32 px） | ±16 px |
| 位置合わせ領域の配置 | ボタン（自動配置 / すべて消去） | 自動配置 |
| 参照フレーム | 上位N%（5〜50%） | 25% |
| 参照の反復精密化 | チェックボックス | ON |

APサイズを変えると中央プレビューのAPオーバーレイが即座に更新される（再解析はしない）。

### 4.2 Quality

| 項目 | UI | 既定値 |
|---|---|---|
| 品質指標 | ポップアップ（勾配エネルギー / 周波数帯パワー比） | 勾配エネルギー |
| バイトオーダー | ポップアップ（自動 / little / big） | 自動 |
| ビット深度の解釈 | ポップアップ（ヘッダ / 12bit / 14bit） | ヘッダ |

品質評価が完了すると左の品質グラフを更新し、アライメントタブへ案内する。

### 4.3 Stack

| 項目 | UI | 既定値 |
|---|---|---|
| フレームの選択方式 | セグメント（割合 / 枚数） | 割合 |
| 位置合わせ領域ごとの採用量 | スライダー + 数値（1〜100% / 枚数） | 10% |
| 輝度正規化 | チェックボックス | ON |
| 加算方式 | ポップアップ（単純平均 / 品質重み付き / σクリップ） | 単純平均 |
| 低メモリモード | チェックボックス（ワーキングセット2GB上限） | 自動判定 |

### 4.4 Drizzle

| 項目 | UI | 既定値 |
|---|---|---|
| 倍率 | セグメント（1× / 1.5× / 2× / 3×） | 1×（無効） |
| pixfrac | スライダー（0.5〜1.0） | 0.9 |

> **常時表示する注意書き（設計原則1.4）**
> 「Drizzleが有効なのは、撮像がアンダーサンプリングされている場合だけです。
> 焦点距離が十分長く既にオーバーサンプリング気味なら、倍率を上げても解像度は
> 向上しません（ファイルサイズと処理時間だけが増えます）。」

倍率が1×以外のときは、推定出力サイズと推定メモリ使用量をその場に表示する。

### 4.5 Wavelet

RegiStax風の6レイヤー。**ここだけは操作の即応性が最優先**であり、
スライダーを動かした瞬間にプレビューが変わることが体験の核になる。

```text
        Sharpen        Denoise
Layer 1 ──●────  0.15   ──●──  0.40
Layer 2 ────●──  0.35   ─●───  0.20
Layer 3 ───●───  0.25   ●────  0.05
Layer 4 ─●─────  0.10   ●────  0
Layer 5 ●──────  0      ●────  0
Layer 6 ●──────  0      ●────  0

[プリセット ▾]  [すべてリセット]
```

- 分解はスタック完了時に1回だけ行い、スライダー操作では軽い再構成だけを行う
- 「ウェーブレット効果をプレビュー」で、同じスタック結果の効果あり/なしを即座に比較できる
- ON/OFFは表示比較だけに作用し、書き出しには設定中の効果を適用する
- 応答目標: 推奨環境 <100ms / 最低環境 <500ms（仕様書 §7.2）
- ドラッグ中は低解像度で追従し、指を離したら本解像度で確定する
  （旧型機でもスライダーが引っかからないようにするため）

### 4.6 Export

| 項目 | UI | 既定値 |
|---|---|---|
| 形式 | ポップアップ（16bit TIFF / 32bit float TIFF / 32bit float FITS / PNG） | 16bit TIFF |
| 出力先 | パス選択 | 入力と同じフォルダ |
| ファイル名 | テキスト（規則のプレビュー付き） | `{元名}_ap{AP}_{率}pct_x{倍率}.tif` |

割合指定時は`{率}pct`、枚数指定時は`{枚数}frames`をファイル名へ入れる。

## 5. 中央プレビュー

### 5.1 表示モード

ツールバーのセグメントで切り替える。

1. **フレーム** — 入力の1枚を表示。スライダーでフレーム送り
2. **参照** — 生成された参照フレーム
3. **結果** — スタック結果（後処理の適用前/後をトグル可能）

### 5.2 APオーバーレイ

- 自動配置されたAPを矩形で描画。中心に小さな十字
- **クリックでAP追加、選択して Delete で削除**
- 解析後は、APごとの平均品質を色（寒色→暖色）で示すヒートマップ表示に切替可能。
  「どこが最後までシーイングに負けていたか」が分かる

### 5.3 描画実装

- Core Graphics による CPU 描画（Metal非対応GPU機に対応するため）
- 256pt角のタイルに分割した `CGImage` をキャッシュし、可視範囲のみ描画
- ズーム倍率ごとに別レベルのタイルを持つ（ミップマップ相当）
- 応答目標: 操作から表示更新まで <100ms（60fpsは要求しない）

## 6. 主要ワークフロー

```text
① ファイルをドラッグ&ドロップ
       ↓
② 自動でヘッダを読み、キューに追加
   ・Bayerなら自動デバイヤー
   ・バイトオーダーが怪しければ警告バナー（§7.2）
       ↓
③ 品質指標と入力の読み方を確認
       ↓
④ [品質評価] を押す ─────→ 品質グラフを表示して停止
       ↓
⑤ 位置合わせ方法・領域の大きさ・探索範囲を確認し、[アライメント] を押す
       ↓
⑥ 参照画像と位置合わせ領域を確認し、採用量と加算方式を決めて [スタック] を押す
       ↓
⑦ 結果を見ながらウェーブレットを調整（即時プレビュー）
       ↓
⑧ [書き出し]
```

- ③〜⑥は繰り返せる。**採用量だけを変えた⑥のやり直しは品質評価とアライメントをスキップする**
- キューに複数ファイルがある場合は [すべて処理] で同一設定のバッチ実行

## 7. 状態表示とエラー

### 7.1 進捗

下部ステータスバーに1行で表示する。

```text
解析中 ████████████░░░░░░  62%   1,860 / 3,000 フレーム   残り約 1分20秒   ⊗
```

- フェーズ名を明示（解析中 / スタック中 / 書き出し中）
- 残り時間は直近の処理速度の移動平均から推定する
- `⊗` でキャンセル。キャンセル後も解析済みの範囲はサイドカーに保存する
- 完了時にユーザー通知（`NSUserNotification` 相当）を出す

### 7.2 警告バナー

プレビュー上部に、閉じられる帯として表示する。CLIの `info` が出す診断と同じ内容を、
GUIでも見逃さないようにする（README「画像が破綻して見えるときの診断手順」に対応）。

| 状況 | 文言と操作 |
|---|---|
| バイトオーダーがヘッダと食い違う | 「ヘッダはbigと記録していますが、自動判定ではlittleと判断しました。画像が破綻して見える場合は切り替えてください」＋ [littleを使う / bigを使う] |
| 16bitヘッダだが実測12bit幅 | 「12bitデータが16bitコンテナに入っている可能性があります。このままでは画像が暗くなります」＋ [12bitとして扱う] |
| 追跡失敗フレームを除外した | 「N枚のフレームを自動除外しました（視野外・追跡失敗）」＋ [詳細を見る] |

### 7.3 エラー

`NSAlert` はファイルを開けない等の致命的な場合に限る。処理中の個別フレームの問題は
バナーとログに留め、処理を止めない。

## 8. AppKit実装上の注意

10.13対応のため、以下を守る（実装計画書 §2）。

- **SwiftUI・Swift Concurrency は使用不可**。`NSSplitViewController` +
  `NSStackView` + `NSTableView` で構成する
- **Metal を前提にしない**。プレビューは Core Graphics
- エンジンはバックグラウンドキュー（GCD）で実行し、進捗コールバックをメインキューへ転送する
- 10.14以降のダークモードは自動で効くが、**機能をOSバージョンで分岐させない**。
  外観差は許容し、10.13でもすべての機能が使えること
- カスタム描画では `NSColor` のシステムカラーを使い、ダークモードに追従させる
- UI言語は日本語・英語。`ja.lproj` / `en.lproj`をバンドルし、macOSの優先言語に
  `NSBundle`標準の選択で追従する。設定キー・プリセット名・ファイル名は翻訳しない
